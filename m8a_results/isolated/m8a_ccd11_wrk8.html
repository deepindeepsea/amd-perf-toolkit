B · Pattern Analysis

DRAM / LLC thrashing HIGH

L2 DC hit rate 48.9% — working set exceeds the 1 MB L2 per core. Data is spilling to L3 or DRAM. Bare-metal Genoa DRAM latency ~80 ns; EPYC 9684X has 96 MB L3 per CCD (3D V-Cache) which helps but random access still creates pipeline bubbles.

Common workloads:

  • Large in-memory databases with random key access
  • Sparse matrix operations
  • Graph traversal with pointer-heavy structures

Recommendations:

  • Tiling/blocking: keep hot working set under ~800 KB to stay in L2
  • Software prefetching: __builtin_prefetch() 30-60 cycles ahead
  • NUMA-aware allocation: numactl --localalloc
  • Data layout: columnar (SoA) outperforms row-major (AoS) for SIMD and cache
Frontend bottleneck HIGH

88.6% of dispatch slots lost in the frontend. The fetch/decode stage is not keeping the backend supplied. Likely: large instruction footprint exceeding L1I (32 KB), micro-op cache thrashing, or branch resteer penalties.

Common workloads:

  • JVM / CPython bytecode dispatch
  • Heavy virtual dispatch (vtables)
  • Hot path spanning many cache lines

Recommendations:

  • Profile-guided optimization (PGO): -fprofile-generate → run → -fprofile-use
  • Link-time optimization: -flto=thin (clang) or -flto (gcc)
  • BOLT / Propeller for post-link code layout optimization
Branch misprediction pressure MEDIUM

3.63% branch misprediction rate, 1.96% of slots wasted. Each misprediction on Zen4 costs ~15-20 cycles. At 3.748 GHz that is ~4-5 ns per event.

Common workloads:

  • Data-dependent conditionals on unpredictable input
  • Interpreter dispatch loops
  • Sort/search on unsorted data

Recommendations:

  • Branchless code: replace if/else with conditional moves (cmov)
  • Lookup tables: replace branch trees with array-indexed dispatch
  • Sort input data before processing to improve branch predictability
  • PGO: let the compiler see real branch probabilities
